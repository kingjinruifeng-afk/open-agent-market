# Bounded buyer-demand pilot / 买方需求验证

Status: preparation only. No real buyers, seller integration or demand is claimed by this document.

## First hypothesis

A personal agent helps a person compare two or three software/service offers within a budget, excluding unapproved extras and making first-period versus recurring cost visible. This is a candidate test alongside ordinary-goods support, not a validated pivot or a claim that OAMP executes subscriptions.

Start with comparison and approval previews. A real-charge pilot follows only after the host meets the approval/checkout requirements and the participants explicitly consent. Do not subscribe to trials, spend money or contact developers as a side effect of preparing this plan.

## Entry gates

- A named host maintainer and one reproducible actual runtime path; do not count the local demo as a host integration.
- Two or three seller-authorized offers with maintained price, fees, renewal, cancellation and source versions; missing facts stay unknown.
- A buyer-controlled budget and extras/recurrence policy, trusted approval interface, private key isolation and a durable consent record before actual spending.
- A clear comparison coverage statement and disclosed recommendation incentives/relationships. A source link or signed statement is not truth verification.
- Before real charges: lawful checkout, current stock/availability where applicable, external payment controls, cancellation/refund responsibility and a stop procedure.

## Record one attempt

Use a consented pseudonymous attempt ID. Store private details with the participant; publish only authorized aggregates.

| Field | Record |
|---|---|
| User task and starting method | What the person needed; how they would ordinarily compare. |
| Host and offer versions | Actual runtime/adapter and source versions, with known limitations. |
| Outcome | Comparison completed, approved agreement, independently evidenced purchase, rejected or abandoned. Keep these separate. |
| Missing/conflicting terms | Unknown fees, renewal conditions or unsupported seller claims; whether the agent stopped. |
| Corrections | Number and nature of user corrections; do not invent a quality score. |
| Cost | Tool calls, model calls, measured tokens/cost where available, user time and maintainer effort. |
| Repeat use | The user actually tries again; stated willingness is recorded separately. |
| Evidence and consent | Type, provenance, permission for any public summary; no keys, addresses, raw billing IDs or private evidence in GitHub. |

Compare like-for-like tasks when measuring time savings. Local operation counts, interest, stars, follows and trial reminders are not proof of saved time or successful commerce.

## Feedback ledger template

For each feedback item: source link/date, exact problem, hypothesis versus observed failure, affected module, proposed bounded task, acceptance evidence, owner/status and unresolved dependency. Deduplicate threads and mark existing replies before sending anything.

## Next-stage trigger

Proceed beyond one scenario only when an actual host runs the workflow, missing terms stop correctly, users complete useful comparisons and measured costs are recorded. Set sample size and business thresholds with the pilot owner before recruitment. Gate B still additionally requires independent operators, interoperable hosts, real commerce/trust evidence and operational readiness; this smaller discovery exercise does not relax Gate B.

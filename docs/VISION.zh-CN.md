# 让个人 Agent 能直接参与的开放交易网络

[English](VISION.md) · [简体中文](VISION.zh-CN.md)

## 我们希望实现的未来

一个人向自己的 Agent 描述需求。Agent 在网络中寻找适合的商品和服务，核对价格、条件和证据，再与卖方 Agent 交流有针对性的问题，给出可解释的比较。当主人选择报价，双方记录约定，通过外部支付和履约服务完成交易，并把反馈带入下一次关系。

卖方通过 Agent 描述一次供给：授权店铺导出、照片、语音或结构化输入。Agent 提醒补足字段，发布有签名和版本的信息，基于维护的知识回答常见问题，并及时更新价格、上下架和可访问状态。

双方不必把全部身份和信誉历史交给一个不可替换的中心平台。多个发现、托管和证据服务可以在共同规范下竞争，参与者按服务质量选择运营者。

这是长期愿景。当前参考实现只验证普通实物商品的一部分流程，并未完成这里描述的全部未来。

## 访问、结构和信任

Agent 可以模拟人操作网站，但交易网络不能只依靠这种方式。页面结构、访问限制、字段不一致、价格时效和平台专属身份都会成为不稳定因素。增加浏览器自动化不能自然产生可迁移的约定、签名价格版本，以及能说明来源的信誉结果。

我们希望为卖家和开发者提供另一条路径：从一开始就面向 Agent 的开放供给和交互协议。它要同时降低发布一份可用供给的成本，以及另一个 Agent 理解和核验它的成本。

这不意味着现有平台必须消失。品牌官网、卖家页面、支付、配送和商家工具仍有价值。协议明确各自的职责，使某个专业服务的访问权不至于变成对全部关系的控制权。

## 协议应该管什么

核心包括身份与签名授权、带版本和来源的供给、服务端点和近期在线证明、报价与接受、最小交易关联和证据承诺、评价归属，以及申诉和更正程序。

Agent 需要明确的失败语义。报价过期、依赖缺失、版本过旧、评审不足和预算耗尽，都应返回结构化条件，而不是要求 Agent 从面向人的页面中猜测。

核心要足够小，允许第三方独立实现。商品领域、物流、库存预留、支付证明、预订日期和地区要求，采用明确的版本化扩展。宿主适配器遵循个人 Agent 原有工具和授权机制。

## 数据存在哪里

卖方维护权威商品材料。参与者保管密钥、私人偏好和私密证据。自主选择的存档保留约定范围的公开签名历史。搜索和信誉服务从历史建立投影，并声明覆盖范围。

每个参与者不必接收全网事件。发现可按类别、社区或地理范围组织，通过分页、字段选择和选择性复制限制消耗。个人 Agent 不应为了买一件商品就变成全网搜索引擎。

大图片、长详情和稳定参数优先复用已授权资源。品牌页面可以说明参数来源，不能证明本卖家的真品、库存、质保或客户体验。外链不可达时，最小字段仍应可读。

存储、带宽和在线服务有成本。运营者需要透明的容量、保留、导出和收费政策。志愿中继或内容寻址链接不能被当成免费永久存储承诺。

## 持续身份与双向信誉

卖方逐步积累描述准确性、质量、发货和服务记录；买方积累付款沟通、交接和正常售后配合记录；评审贡献单独记录，不直接提高商家商业评分。

这些信息不应压缩成一个强制唯一的总分。时间紧迫的采购与二手商品购买，对发货、质量、价格和维修性的权重不同。Agent 应看到维度、样本、时间、来源和不确定性，才能解释比较。

自由身份有助于开放接入，但多个公钥不证明独立的人，签名也不证明真实成交。交易图可以伪造。生产信任需要证据分级、重复互评影响限制、关系披露、适当外部证明和实际攻击测试。

全球实名不是国际试点前提。未来可以接入可选认证属性，但不应形成新的全网准入垄断。

## 公平评审与普通维权

退货、退款、差评和争议是正常交易的一部分。把它们直接标为可疑，会伤害项目希望服务的人。诚信判断必须与产品低分、普通败诉和责任分配分开。

客观规则可以检验签名、授权、版本和程序。争议事实需要证据与有能力、独立的判断者。Agent 可以辅助摘要和解释规则，不能假装是独立的人类评审者。

参考版本探索3人初审、5人不重叠复审、意见先承诺后公开、严重标签在申诉窗口后生效，以及新证据更正机制。它们是程序实验，不是法律仲裁，也不是已经完成的去中心化法院。

评审激励应重视负责任的贡献和证据质量，不能鼓励迎合多数或刷判案数量。隐藏串谋、专业匹配、随机性和利益冲突仍是难题。我们欢迎反例来推动可验证的改进。

## 在线与效率

活跃供给应能够接受进一步交互。长期在线宿主维持服务端点；个人部署停止后，供给过期退出活跃检索，历史由约定档案继续保留。

分布式检测不能保证故障瞬间全网立即知道。参考实现使用短期签名在线证明并明确缓存窗口。在线证明也不等于库存预留，不担保一笔具体订单履约。

大部分访问应该便宜：字段校验、筛选、验签、静态参数、FAQ、缓存和按需读取。剩余个性化问题再使用模型。宿主需要并发、超时、带宽和模型预算；持续在线不代表无限算力。

## 如何成为有用的开源项目

先提供可复现实现和可独立实现的契约，再由两种实际宿主、两个真正独立的运营者验证互通与迁移。真实买卖场景帮助判断发布与发现是否方便到值得改变流程。

试点需测量成本、价格时效、召回价值、询价成功、私密证据处理、迁移、维权保护和运营经济性。攻击测试覆盖伪造收据、串谋评价、事件分叉、卖家不可达和评审选择操纵。

关注和增长应来自有用的集成与可信的证据。我们希望通过能运行的例子、诚实的边界、及时的议题响应，以及参与协议演进的机会，吸引开发者。

## 邀请参与

个人 Agent 开发者可以带来一个用户今天无法可靠完成的交易任务；商家工具开发者可以降低发布成本；协议和安全开发者可以挑战身份、信誉与迁移；独立运营者可以验证真实节点故障下的可迁移性。

当参与者可以选择自己的 Agent 和服务提供者，同时保留发现供给、相互交互和携带历史的能力，这个项目才实现价值。[路线图](ROADMAP.md)记录可以一起推进的工作。

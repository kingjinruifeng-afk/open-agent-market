# 个人 Agent 开放交易网络 · 优化执行计划

日期：2026-10-11。工作名称 Open Agent Market，仅用于参考实现，不声称名称唯一。此文件替换聊天中的旧计划，是当前执行入口。

## 目标与边界

提供个人 Agent 可直接调用的开放供给、询价、交易证据、双向信誉和第三方评审接口。身份和证据可迁移，节点运营者可替换；不要求实名，不发行代币，不依赖区块链，不执行资金托管。首个场景为普通实物商品，服务领域通过版本化能力扩展。

完整角色：主体、买卖 Agent、宿主/网关、资源提供者、目录/中继、搜索、在线检测、独立存档、信誉计算、纠纷协调、评审、审计、外部付款/物流、协议维护。参考节点复用多个职责；独立部署不等于独立运营。

## 数据与交互

主体持有私钥、恢复材料及私密业务资料。卖方持有当前商品与知识。双方持有交易证据。独立档案保存公开事件并提供签名检查点与导出；搜索/评分为可重建投影。大文件保留外部来源引用，未来镜像需明确授权和存储承诺。

HTTPS/JSON 为公共接口；事件签名、字段选择、游标分页、批量获取、预算和明确错误是核心契约。参考开发监听 localhost；公网须 TLS、运营者准入/限额、备份与安全评估。

发布采用单写者版本和 previous 链；交易采用多方独立事件。报价绑定商品版本、买方、期限和私密条款加盐承诺；接受必须匹配有效报价。不会把报价当库存预留。

在线状态使用节点签名近期证明，默认最多 10 秒，允许来源列表防止 SSRF；一次并发探测复用。失败剔除活跃供给，历史仍保留。身份与卖方服务故障不能等同于历史失效。

技能支持结构化导入/草稿、缺字段检查、来源标注、知识分层、预算建议；实际照片/语音解释由宿主提供。核心不自动抓取受限网站、不声称兼容未验证的 Muse/Grok 产品。

## 身份、信誉与纠纷

冷存根身份可授权操作键；提供轮换、预登记恢复和撤销。同一主体的买方、卖方、评审维度分开。首版参考信誉输出交易样本、评分分布、证据分组、时间范围、判责标签，不输出未经证据支持的已验证成功率。

正常退货/退款/差评不扣诚信分；自报付款/发货不成为独立验证证据。高分不能证明身份独立，也不能代替评审资格。

试点评审池在策略中明确配置，资格来源标记 bootstrap。排除当事人与已知直接交易关联。3 人初审、5 人复审且不重叠，先独立提交承诺再揭示有理由结论。仅处理信誉和建议，分为责任与诚信；允许证据不足。评审者本人确认并签名，Agent 仅辅助。

预先公布规则、阶段期限和费用。初审后有申诉窗口，严重标签不提前生效。复审/更正可取消标签；不自动处罚少数意见或被推翻的评审者。贡献标签与商家信用分分离；模拟评审不证明称号激励有效。

## 节点运营

项目方提供有容量上限的参考节点；合作 Agent 开发者/商家服务商提供独立节点；后续专业服务商收取透明容量/托管费。身份、导出、迁移不被某一节点独占。志愿节点仅为补充，不承诺免费永久保存。

每个节点声明运营者、能力、费用、限额和保留期限。付费不能购买信誉或有利判责。GitHub 维护者负责代码；节点运营者负责部署、安全、备份和数据合同。

Gate A 命令：`npm run check`、`npm run demo`、`npm run benchmark`。Python 跨语言测试使用真实解释器；没有解释器必须显示未验，不得静默跳过后宣称全通过。检查入口由实现提供。

Gate B：至少两个真实独立运营者、两种实际宿主路径、真实商家与需求、充足独立评审池、真实争议处理、成本与付费意愿、针对反串通和公网攻击的审查。缺证据则维持 experimental。

执行进度：T01—T06参考实现完成；T07—T08本地部分完成，21项测试、实际Python互通、3进程故障演练、Demo与500商品实测通过。容器未实测，云端CI以发布记录为准；T09已获GitHub发布授权，但尚缺真实宿主/运营者。证据与剩余工作以 [STATUS.md](STATUS.md) 为准。

## 停止条件与发布

数据泄漏、历史不可迁移、正常维权被处罚、标签不能纠正时暂停扩大试点。记录证据、修复并重跑受影响检查。

代码采用 Apache-2.0。2026-10-11项目所有者已授权向其GitHub账号发布并每日运营；目标为 `kingjinruifeng-afk/open-agent-market`。代码开源发布与生产网络就绪分别验收，不把发布或测试通过当作真实交易试点成功。

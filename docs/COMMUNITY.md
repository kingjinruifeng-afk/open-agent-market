# Community operations / 社区运营

The project earns attention through clear documentation, working integrations and responsive collaboration. We do not manufacture stars, endorsements, transactions or independent reviewer identities.

Daily stewardship, authorized by the project owner:

- Inspect new issues, discussions, PRs and CI changes using the repository's public APIs or authorized connection.
- Answer routine technical questions with source/verification context; ask for missing reproducible details without requesting secrets.
- Triage work against the roadmap and keep English/Chinese docs consistent. Substantial implementation changes go through a reviewable PR and do not merge automatically.
- Report meaningful failures, contributor activity, adoption evidence or decisions requiring the owner. Stay quiet when nothing actionable changed.

Use the owner's project account only for this repository's normal maintenance. No unsolicited messages, comments in other people's repositories, social-media campaigns, paid promotions, spending commitments or production hosting without a separate concrete instruction.

Initial engagement focuses on a welcome thread, real host adapters, bounded discovery, conformance work, trust review and independent operators. These are maintainer-created invitations, not evidence of existing external demand. Star/fork counts can show attention but do not prove adoption.

Initial success evidence: a developer reproduces the demo; a host adapter runs a real workflow; an independent implementation validates the protocol; an independent operator completes export/recovery; a buyer and seller report a useful consenting pilot. Use cases and counterexamples matter more than vanity metrics.

每日运营检查新议题、讨论、PR及CI，处理常规问题并整理路线图。有重要变化才通知；不得刷关注、伪造用户、冒充独立评审，或未经额外指示在其他项目和社交平台投放推广。真实集成与互通证据优先于星标数量。
